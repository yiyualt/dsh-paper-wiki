# 论文百科

DeepSeek Harness Web 插件。沿用「代码百科」的文档库和生成进度，读取本地 PDF 论文，以固定案例窗口和紧凑图解讲清任务、方法和实验证据。

## 安装

需要 Node.js 22.13.0 或更高版本。进入项目目录后运行：

```sh
npm ci
npm run check
npm pack
dsh plugin --profile web add ./dsh-paper-wiki-0.4.1.tgz
```

也可在 DSH「插件 → 添加插件」中输入安装包的绝对路径，安装后启用。如果 DSH 提示重启，使用原启动命令重启 Web 服务。依赖 PDF.js 会随插件安装，首次安装需要访问 npm 或已有依赖缓存。

## 使用

1. 在侧栏打开「论文百科」，点击右上角「新建 Wiki」，选择论文。
2. 手动点击「生成讲解」，插件读取 PDF 后生成讲解。选择文件、打开或刷新页面都不会自动调用模型；没有单独的导入步骤。
3. 生成完成后，在顶部导航选择主题。左侧固定案例窗口用阶段、文件和代码行说明输入到输出；右侧用流程、对照、关系和结果图组织讲解。界面仅展示讲解，不展示 PDF 或提取的逐页文字。
4. 阶段和文件只切换案例；带标记的代码行在原处显示对应内容。顶部目录负责正文跳转，右侧图表在组件内更新，不自动更换案例或滚动页面。详细术语与推导按需展开。讲解保留页码依据，可导出为同样布局与交互的离线 HTML；旧版内容仍可阅读和导出。

任务在 DSH 服务后台运行，切换面板或刷新页面后可查看进度；取消后可以重新生成。重启 DSH 会中断正在执行的任务。重新生成成功后更新讲解，失败时保留此前保存的版本。生成完成后，论文库只保留论文列表及「已讲解」状态。

升级后，已有的段落版、Markdown 或分章讲解仍可阅读。打开旧文档不会重新生成或发起模型请求；需要新版内容时，手动点击「重新讲解」。

## 讲解内容

新版生成实际加载随插件打包的 `skills/paper-explainer/SKILL.md` 和相关教学参考，先设计共享案例与图解，再填充紧凑讲解，最后审核事实与教学质量。同一 skill 也可在 Codex 中作为 `$paper-explainer` 使用，支持独立论文精讲和 HTML 成品。

- 讲解须能独立读懂：用具体输入输出建立任务，就地定义概念，沿同一案例交代基线、作者操作与中间结果，再以实验条件和观测限定结论；必要推导不因精简而省略。
- 图解承担主要说明，正文只补充图中看不到的原因和结论；避免重复案例、图注和长段文字。
- 核心术语结合代码行和简短说明解释，定义与微例可按需展开。「论文实例」依据论文原文；「构造示例」明确标注，不充当论文实验结果。
- 深色代码窗、阶段标签、语法配色、行高亮、状态颜色和数值条统一阅读层级。方法图只显示当前相关解释，避免将全部节点、边和推导常驻展开。
- 公式计算使用受限算术表达式，由程序求值；构造输入可调整，论文观测值保持只读。右侧参数只重算该组件的数值，不改原始案例，也不声称执行过论文模型。应用与离线导出共用受信任的 HTML 模板和交互代码，不执行模型提供的 JavaScript。
- 内容直接采用具体主题，不插入「注意」「解释」「提示」等编辑性标签；作者原有表述和专业术语保留原意。
- 数值对比图只使用能在对应页原文中核对的数据，并保留比较条件、指标和单位。未提取到的图表数据不会补写。

插件在本地为论文文字片段生成 ID，模型选择片段 ID 后，插件服务器映射回对应原句和 PDF 页码，再进行原句精确匹配检查。模型仍会审核事实依据和关键内容是否覆盖；可定位到章节的校验或审核问题只修订相关章节，其他章节复用，最多修订一次，仍不通过则报告失败。此检查不能保证对公式、图表或研究结论的解释完全准确，阅读时可用页码标注对照本机原文。

## 支持范围

支持有可提取文字的 PDF，单文件最多 30 MiB、150 页，提取文字最多 600,000 字符。中文讲解最多处理 120,000 字符的提取文字；超过限制会明确提示，不会截断后声称已读完整篇论文。

扫描件、仅含图片的 PDF 和加密 PDF 会提示无法读取。没有文字层的图表、复杂排版和公式可能无法完整提取，需要自行打开本机 PDF 核对；文件读取成功不代表每个图表都已被模型读取。

## 模型配置与数据

默认使用 DSH 当前默认模型及其凭据。若需要与「代码百科」使用同一个单独配置的服务，可为本插件设置相同的 `modelConfigFile`；它不会自动继承其他插件的设置。

在当前 profile 的 `cordis.patch.yml` 中设置：

```yaml
- id: dsh-paper-wiki
  config:
    modelConfigFile: /absolute/path/config.local.json
```

该 JSON 文件沿用「代码百科」的 `judge` 配置格式，例如：

```json
{
  "judge": {
    "url": "https://your-provider.example/v1/chat/completions",
    "model": "your-model",
    "api_key_env": "YOUR_MODEL_API_KEY"
  }
}
```

PDF 文字提取在本地完成。手动点击「生成讲解」后，插件会把提取的论文文字、引用及讲解草稿发送到所选模型服务。模型配置文件和凭据不随插件打包。

数据保存在当前 DSH profile：

```text
dsh-paper-wiki/
└── papers/
    └── <论文编号>/
        ├── paper.json
        └── original.pdf
```

`paper.json` 保存论文元数据、逐页文字及已通过检查的讲解；`original.pdf` 保存导入时的 PDF。删除论文会删除这两项存档，源文件不受影响。

## 开发检查

```sh
npm test
npm run build
npm run check:package
```

`npm run check` 顺序执行以上检查。安装包检查在临时目录离线安装生成的包，验证发布文件清单、JavaScript 语法、入口导出、PDF.js 依赖和浏览器构建产物。离线安装需要先完成一次 `npm ci`，让依赖进入 npm 缓存。检查包含 skill 加载、教学设计覆盖、公式计算、关系与预算结构、离线 HTML 完整性及引用准确性；教学效果仍需结合具体论文和实际阅读验收。
